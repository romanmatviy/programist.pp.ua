        <h2>Вступ: Що приховує помилка 500?</h2>
        <p>Повідомлення **500 Internal Server Error** (Внутрішня помилка сервера) є однією з найбільш розчаровуючих проблем для веб-майстрів та користувачів сайту. Цей код стану HTTP є загальним повідомленням, яке каже лише про одне: на сервері сталася непередбачена критична помилка, але сервер не може деталізувати її причину в цілях безпеки.</p>
        <p>У цій статті ми детально розглянемо перевірений алгоритм діагностики та швидкого усунення цієї помилки на будь-якому веб-сайті.</p>
        
        <h2>1. Читання логів помилок сервера (Error Logs)</h2>
        <p>Ніколи не намагайтеся вгадати причину помилки. Перше і головне правило професіонала — вивчити системні логи сервера. Саме там ви знайдете точний опис файлу та номер рядка коду, які спричинили падіння системи.</p>
        <ul>
          <li><strong>У веб-сервері Apache / Nginx:</strong> Перевірте файл <code>error.log</code>, який зазвичай знаходиться за шляхом <code>/var/log/nginx/error.log</code> або <code>/var/log/apache2/error.log</code>.</li>
          <li><strong>У WordPress:</strong> Активуйте вбудований режим налагодження. Відкрийте файл <code>wp-config.php</code> та змініть конфігурацію:
            <pre><code class="language-php">define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );</code></pre>
            Після цього всі помилки будуть записуватися у файл <code>wp-content/debug.log</code>.
          </li>
        </ul>

        <h2>2. Пошкодження файлу .htaccess</h2>
        <p>На хостингах, які використовують веб-сервер Apache, помилка 500 дуже часто викликана синтаксичною помилкою у файлі додаткових конфігурацій <code>.htaccess</code>. Наприклад, неправильний запис правил перенаправлення (RewriteRules).</p>
        <p><strong>Рішення:</strong> Перейменуйте файл <code>.htaccess</code> у <code>.htaccess_old</code> через менеджер файлів або FTP та спробуйте оновити сторінку. Якщо сайт запрацював — перегенеруйте правила з нуля (для WordPress достатньо зайти в Налаштування -> Постійні посилання та просто натиснути кнопку "Зберегти").</p>

        <h2>3. Перевищення ліміту оперативної пам'яті PHP (Memory Limit)</h2>
        <p>Якщо ваш веб-сайт використовує складні модулі обробки зображень або робить великі вибірки з бази даних, скрипт може досягти максимального ліміту пам'яті, виділеної для виконання PHP процесу.</p>
        <p><strong>Рішення:</strong> Збільште ліміт оперативної пам'яті. Ви можете зробити це, додавши наступний рядок у файл <code>.htaccess</code>:</p>
        <pre><code class="language-apache">php_value memory_limit 512M</code></pre>
        <p>або безпосередньо в конфігураційному файлі <code>php.ini</code>:</p>
        <pre><code class="language-ini">memory_limit = 512M</code></pre>

        <h2>4. Неправильні дозволи доступу до файлів та папок</h2>
        <p>Занадто високі права доступу (наприклад, 777 на файли) можуть блокуватися системами безпеки сервера (suPHP, mod_security) для запобігання несанкціонованому запису даних.</p>
        <p><strong>Стандарт безпеки:</strong> Переконайтеся, що всі папки мають права <strong>755</strong>, а всі файли — <strong>644</strong>. Ви можете швидко виправити дозволи через термінал за допомогою наступних команд:</p>
        <pre><code class="language-bash">find . -type d -exec chmod 755 {} \;
find . -type f -exec chmod 644 {} \;</code></pre>

        <h2>Висновок</h2>
        <p>Помилка 500 Internal Server Error майже завжди криється в дрібницях: помилка синтаксису у файлі конфігурації чи нестача системних ресурсів. Використовуючи послідовну діагностику через читання логів помилок, ви зможете повернути ваш сайт до ладу за лічені хвилини.</p>
