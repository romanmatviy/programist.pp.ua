## Вступ: Що приховує помилка 500?

Повідомлення **500 Internal Server Error** (Внутрішня помилка сервера) є однією з найбільш розчаровуючих проблем для веб-майстрів та користувачів сайту. Цей код стану HTTP є загальним повідомленням, яке каже лише про одне: на сервері сталася непередбачена критична помилка, але сервер не може деталізувати її причину в цілях безпеки.

У цій статті ми детально розглянемо перевірений алгоритм діагностики та швидкого усунення цієї помилки на будь-якому веб-сайті.

## 1. Читання логів помилок сервера (Error Logs)

Ніколи не намагайтеся вгадати причину помилки. Перше і головне правило професіонала — вивчити системні логи сервера. Саме там ви знайдете точний опис файлу та номер рядка коду, які спричинили падіння системи.

* **У веб-сервері Apache / Nginx:** Перевірте файл `error.log`, який зазвичай знаходиться за шляхом `/var/log/nginx/error.log` або `/var/log/apache2/error.log`.
* **У WordPress:** Активуйте вбудований режим налагодження. Відкрийте файл `wp-config.php` та змініть конфігурацію:

```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
```

Після цього всі помилки будуть записуватися у файл `wp-content/debug.log`.

## 2. Пошкодження файлу .htaccess

На хостингах, які використовують веб-сервер Apache, помилка 500 дуже часто викликана синтаксичною помилкою у файлі додаткових конфігурацій `.htaccess`. Наприклад, неправильний запис правил перенаправлення (RewriteRules).

**Рішення:** Перейменуйте файл `.htaccess` у `.htaccess_old` через менеджер файлів або FTP та спробуйте оновити сторінку. Якщо сайт запрацював — перегенеруйте правила з нуля (для WordPress достатньо зайти в Налаштування -> Постійні посилання та просто натиснути кнопку "Зберегти").

## 3. Перевищення ліміту оперативної пам'яті PHP (Memory Limit)

Якщо ваш веб-сайт використовує складні модулі обробки зображень або робить великі вибірки з бази даних, скрипт може досягти максимального ліміту пам'яті, виділеної для виконання PHP процесу.

**Рішення:** Збільште ліміт оперативної пам'яті. Ви можете зробити це, додавши наступний рядок у файл `.htaccess`:

```apache
php_value memory_limit 512M
```

або безпосередньо в конфігураційному файлі `php.ini`:

```ini
memory_limit = 512M
```

## 4. Неправильні дозволи доступу до файлів та папок

Занадто високі права доступу (наприклад, 777 на файли) можуть блокуватися системами безпеки сервера (suPHP, mod_security) для запобігання несанкціонованому запису даних.

**Стандарт безпеки:** Переконайтеся, що всі папки мають права **755**, а всі файли — **644**. Ви можете швидко виправити дозволи через термінал за допомогою наступних команд:

```bash
find . -type d -exec chmod 755 {};
find . -type f -exec chmod 644 {};
```

## Висновок

Помилка 500 Internal Server Error майже завжди криється в дрібницях: помилка синтаксису у файлі конфігурації чи нестача системних ресурсів. Використовуючи послідовну діагностику через читання логів помилок, ви зможете повернути ваш сайт до ладу за лічені хвилини.
