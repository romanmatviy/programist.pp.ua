        <h2>Вступ: Еволюція архітектури передачі даних</h2>
        <p>Побудова надійного, масштабованого та зручного API є основою розробки будь-якого сучасного веб- чи мобільного додатку. Десятиліттями архітектурний стиль <strong>REST</strong> (Representational State Transfer) був безумовним стандартом. Проте, зі зростанням складності інтерфейсів, з'явилася потреба в більш гнучкому підході, що призвело до створення мови запитів <strong>GraphQL</strong> компанією Facebook.</p>
        <p>Сьогодні розробники часто постають перед вибором: перевірений часом та простий REST чи інноваційний та гнучкий GraphQL? У цій статті ми порівняємо ці дві технології за ключовими параметрами та допоможемо визначитися з вибором для вашого наступного проекту.</p>
        
        <h2>1. Головна проблема REST: Over-fetching та Under-fetching</h2>
        <p>REST API базується на фіксованих кінцевих точках (endpoints), кожна з яких повертає жорстко задану структуру даних на сервері.</p>
        <ul>
          <li><strong>Over-fetching (Надлишок даних):</strong> Уявіть, що на сторінці списку товарів вам потрібно показати лише назву та ціну. Проте ендпоінт <code>/api/products</code> повертає повну структуру з детальним описом, коментарями, повним списком характеристик та історією замовлень. Користувач завантажує гігабайти зайвого JSON-тексту.</li>
          <li><strong>Under-fetching (Брак даних):</strong> Для виведення детальної картки автора, його постів та коментарів до них у REST вам, можливо, доведеться зробити три послідовні мережеві запити: спочатку до <code>/api/users/1</code>, потім до <code>/api/users/1/posts</code>, а після цього отримати коментарі для кожного поста. Це суттєво уповільнює роботу сайту при низькій швидкості мобільного інтернету.</li>
        </ul>

        <h2>2. Перевага GraphQL: Клієнт визначає форму даних</h2>
        <p>GraphQL повністю усуває ці проблеми. Замість десятків ендпоінтів у вас є лише одна кінцева точка (зазвичай <code>/graphql</code>), а клієнтська сторона сама надсилає запит, точно описуючи, які саме поля їй потрібні.</p>
        
```graphql
# Запит до GraphQL на отримання лише необхідних полів
query GetProductBrief {
  product(id: "42") {
    title
    price
    seller {
      name
    }
  }
}
```

        <p>Сервер поверне JSON, що містить виключно ці чотири поля, що значно економить трафік і прискорює відображення даних.</p>

        <h2>Що обрати? Рекомендації</h2>
        <p><strong>Обирайте REST API, якщо:</strong> ви будуєте невеликий проект із простою структурою даних, розробляєте публічне API для сторонніх інтеграцій, або вам критично важливе стандартне HTTP кешування (наприклад, для контентних сайтів).</p>
        <p><strong>Обирайте GraphQL, якщо:</strong> ви будуєте складний додаток із мобільними клієнтами, де структура даних постійно змінюється, дані мають багато зв'язків (на кшталт соціальних мереж чи ERP систем), а швидкість розробки фронтенду має вирішальне значення.</p>
