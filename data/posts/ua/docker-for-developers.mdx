        <h2>Вступ: Чому кожен сучасний розробник має знати Docker?</h2>
        <p>Класична проблема «на моєму комп'ютері це працювало, а на сервері чомусь зламалося» десятиліттями забирала купу нервів та часу у програмістів і системних адміністраторів. Різні версії мов програмування, відсутність необхідних системних бібліотек, конфлікти конфігурацій — все це створювало купу перешкод.</p>
        <p><strong>Docker</strong> повністю розв'язує цю проблему. Завдяки технології контейнеризації він дозволяє упакувати веб-додаток разом з усім його оточенням (ОС, бібліотеки, бази даних, системні налаштування) в єдиний ізольований образ, який гарантовано працюватиме абсолютно однаково на вашому ноутбуці, тестовому сервері чи у хмарі (AWS/GCP/DigitalOcean).</p>
        
        <h2>1. Створення першого Dockerfile для Node.js додатку</h2>
        <p>Файл <code>Dockerfile</code> є текстовою інструкцією, яка описує кроки, необхідні для створення Docker-образу (Docker Image). Давайте напишемо професійний, багатоетапний (multi-stage) Dockerfile для Node.js додатку, який мінімізує вагу фінального образу.</p>
        <pre><code class="language-dockerfile"># Етап 1: Збірка проекту
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Етап 2: Фінальний мінімальний образ для виробництва
FROM node:18-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm install --only=production
COPY --from=builder /app/dist ./dist

EXPOSE 3000
CMD ["node", "dist/index.js"]</code></pre>
        <p>Використання базового образу <code>alpine</code> та розподіл на етапи (multi-stage build) дозволяє скоротити розмір образу з 900МБ до всього 120МБ, що значно прискорить розгортання проекту.</p>

        <h2>2. Локальна оркестрація з Docker Compose</h2>
        <p>Будь-який сучасний сайт складається з кількох взаємопов'язаних сервісів: безпосередньо веб-додатку, бази даних та, наприклад, кеш-серверу Redis. Замість того, щоб запускати кожен контейнер окремо за допомогою довгих термінальних команд, використовують <strong>Docker Compose</strong>.</p>
        <p>Створіть файл <code>docker-compose.yml</code> у кореневому каталозі проекту для швидкого локального запуску всього стеку однією командою:</p>
        <pre><code class="language-yaml">version: '3.8'

services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
      - REDIS_HOST=cache
    depends_on:
      - db
      - cache

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: app_database
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  cache:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:</code></pre>

        <h2>3. Корисний шпаргалка команд Docker для розробника</h2>
        <p>Ось список основних команд, які ви використовуватимете щодня під час роботи з контейнерами:</p>
        <ul>
          <li><code>docker-compose up --build -d</code> — Запустити всі контейнери у фоновому режимі та перезібрати образи.</li>
          <li><code>docker ps</code> — Показати список усіх запущених контейнерів на машині.</li>
          <li><code>docker exec -it [container_name] sh</code> — Увійти всередину працюючого контейнера через командний рядок.</li>
          <li><code>docker logs -f [container_name]</code> — Переглянути логи роботи контейнера в реальному часі.</li>
          <li><code>docker system prune -a --volumes</code> — Повністю очистити систему від невикористовуваних контейнерів, образів та томів, звільнивши дисковий простір.</li>
        </ul>

        <h2>Висновок</h2>
        <p>Docker став галузевим стандартом у сучасній веб-розробці. Його вивчення відкриває перед розробником можливості створення надійного CI/CD процесу та спрощує роботу в команді. Почніть з контейнеризації найпростішого проекту, і ви більше ніколи не захочете встановлювати сервери бази даних безпосередньо у вашу операційну систему.</p>
