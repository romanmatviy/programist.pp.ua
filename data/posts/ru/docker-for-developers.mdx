        <h2>Введение: Почему каждый современный разработчик обязан знать Docker?</h2>
        <p>Классическая проблема «на моем компьютере это работало, а на сервере почему-то сломалось» десятилетиями забирала уйму нервов и времени у программистов и системных администраторов. Разные версии языков программирования, отсутствие необходимых системных библиотек, конфликты конфигураций — всё это создавало множество препятствий.</p>
        <p><strong>Docker</strong> полностью решает эту проблему. Благодаря технологии контейнеризации он позволяет упаковать веб-приложение вместе со всем его окружением (ОС, библиотеки, базы данных, системные настройки) в единый изолированный образ, который гарантированно будет работать абсолютно одинаково на вашем ноутбуке, тестовом сервере или в облаке (AWS/GCP/DigitalOcean).</p>
        
        <h2>1. Создание первого Dockerfile для Node.js приложения</h2>
        <p>Файл <code>Dockerfile</code> представляет собой текстовую инструкцию, описывающую шаги, необходимые для сборки Docker-образа (Docker Image). Давайте напишем профессиональный, многоэтапный (multi-stage) Dockerfile для Node.js приложения, который минимизирует вес финального образа.</p>
        <pre><code class="language-dockerfile"># Этап 1: Сборка проекта
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Этап 2: Финальный минимальный образ для производства
FROM node:18-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm install --only=production
COPY --from=builder /app/dist ./dist

EXPOSE 3000
CMD ["node", "dist/index.js"]</code></pre>
        <p>Использование базового образа <code>alpine</code> и разделение на этапы (multi-stage build) позволяет сократить размер образа с 900МБ до всего 120МБ, что значительно ускорит развертывание проекта.</p>

        <h2>2. Локальная оркестрация с Docker Compose</h2>
        <p>Любой современный сайт состоит из нескольких взаимосвязанных сервисов: непосредственно веб-приложения, базы данных и, например, кэш-сервера Redis. Вместо того, чтобы запускать каждый контейнер отдельно с помощью длинных терминальных команд, используют <strong>Docker Compose</strong>.</p>
        <p>Создайте файл <code>docker-compose.yml</code> в корневом каталоге проекта для быстрого локального запуска всего стека одной командой:</p>
        <pre><code class="language-yaml">version: '3.8'

services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
      - REDIS_HOST=cache
    depends_on:
      - db
      - cache

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: app_database
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  cache:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:</code></pre>

        <h2>3. Полезная шпаргалка команд Docker для разработчика</h2>
        <p>Вот список основных команд, которые вы будете использовать ежедневно при работе с контейнерами:</p>
        <ul>
          <li><code>docker-compose up --build -d</code> — Запустить все контейнеры в фоновом режиме и пересобрать образы.</li>
          <li><code>docker ps</code> — Показать список всех запущенных контейнеров на машине.</li>
          <li><code>docker exec -it [container_name] sh</code> — Войти внутрь работающего контейнера через командную строку.</li>
          <li><code>docker logs -f [container_name]</code> — Просмотреть логи работы контейнера в реальном времени.</li>
          <li><code>docker system prune -a --volumes</code> — Полностью очистить систему от неиспользуемых контейнеров, образов и томов, освободив дисковое пространство.</li>
        </ul>

        <h2>Заключение</h2>
        <p>Docker стал отраслевым стандартом в современной веб-разработке. Его изучение открывает перед разработчиком возможности создания надежного CI/CD процесса и упрощает работу в команде. Начните с контейнеризации простейшего проекта, и вы больше никогда не захотите устанавливать серверы базы данных непосредственно в вашу операционную систему.</p>
