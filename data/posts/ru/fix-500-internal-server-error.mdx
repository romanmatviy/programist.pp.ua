## Введение: Что скрывает ошибка 500?

Сообщение **500 Internal Server Error** (Внутренняя ошибка сервера) является одной из самых разочаровывающих проблем для веб-мастеров и пользователей сайта. Этот код состояния HTTP является общим сообщением, говорящим лишь об одном: на сервере произошла непредвиденная критическая ошибка, но сервер не может детализировать её причину в целях безопасности.

В этой статье мы подробно рассмотрим проверенный алгоритм диагностики и быстрого устранения этой ошибки на любом веб-сайте.

## 1. Чтение логов ошибок сервера (Error Logs)

Никогда не пытайтесь угадать причину ошибки. Первое и главное правило профессионала — изучить системные логи сервера. Именно там вы найдете точное описание файла и номер строки кода, которые вызвали падение системы.

* **В веб-сервере Apache / Nginx:** Проверьте файл `error.log`, который обычно находится по пути `/var/log/nginx/error.log` или `/var/log/apache2/error.log`.
* **В WordPress:** Активируйте встроенный режим отладки. Откройте файл `wp-config.php` и измените конфигурацию:

```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
```

После этого все ошибки будут записываться в файл `wp-content/debug.log`.

## 2. Повреждение файла .htaccess

На хостингах, использующих веб-сервер Apache, ошибка 500 очень часто вызвана синтаксической ошибкой в файле дополнительных конфигураций `.htaccess`. Например, неправильной записью правил перенаправления (RewriteRules).

**Решение:** Переименуйте файл `.htaccess` в `.htaccess_old` через менеджер файлов или FTP и попробуйте обновить страницу. Если сайт заработал — перегенерируйте правила с нуля (для WordPress достаточно зайти в Настройки -> Постоянные ссылки и просто нажать кнопку "Сохранить").

## 3. Превышение лимита оперативной памяти PHP (Memory Limit)

Если ваш веб-сайт использует сложные модули обработки изображений или делает крупные выборки из базы данных, скрипт может достичь максимального лимита памяти, выделенной для выполнения PHP процесса.

**Решение:** Увеличьте лимит оперативной памяти. Вы можете сделать это, добавив следующую строку в файл `.htaccess`:

```apache
php_value memory_limit 512M
```

или непосредственно в конфигурационном файле `php.ini`:

```ini
memory_limit = 512M
```

## 4. Неправильные разрешения доступа к файлам и папкам

Слишком высокие права доступа (например, 777 на файлы) могут блокироваться системами безопасности сервера (suPHP, mod_security) для предотвращения несанкционированной записи данных.

**Стандарт безопасности:** Убедитесь, что все папки имеют права **755**, а все файлы — **644**. Вы можете быстро исправить разрешения через терминал с помощью следующих команд:

```bash
find . -type d -exec chmod 755 {};
find . -type f -exec chmod 644 {};
```

## Заключение

Ошибка 500 Internal Server Error почти всегда кроется в мелочах: ошибка синтаксиса в файле конфигурации или нехватка системных ресурсов. Используя последовательную диагностику через чтение логов ошибок, вы сможете вернуть ваш сайт в строй за считанные минуты.
