        <h2>Введение: Что скрывает ошибка 500?</h2>
        <p>Сообщение **500 Internal Server Error** (Внутренняя ошибка сервера) является одной из самых разочаровывающих проблем для веб-мастеров и пользователей сайта. Этот код состояния HTTP является общим сообщением, говорящим лишь об одном: на сервере произошла непредвиденная критическая ошибка, но сервер не может детализировать её причину в целях безопасности.</p>
        <p>В этой статье мы подробно рассмотрим проверенный алгоритм диагностики и быстрого устранения этой ошибки на любом веб-сайте.</p>
        
        <h2>1. Чтение логов ошибок сервера (Error Logs)</h2>
        <p>Никогда не пытайтесь угадать причину ошибки. Первое и главное правило профессионала — изучить системные логи сервера. Именно там вы найдете точное описание файла и номер строки кода, которые вызвали падение системы.</p>
        <ul>
          <li><strong>В веб-сервере Apache / Nginx:</strong> Проверьте файл <code>error.log</code>, который обычно находится по пути <code>/var/log/nginx/error.log</code> или <code>/var/log/apache2/error.log</code>.</li>
          <li><strong>В WordPress:</strong> Активируйте встроенный режим отладки. Откройте файл <code>wp-config.php</code> и измените конфигурацию:
            
```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
```

            После этого все ошибки будут записываться в файл <code>wp-content/debug.log</code>.
          </li>
        </ul>

        <h2>2. Повреждение файла .htaccess</h2>
        <p>На хостингах, использующих веб-сервер Apache, ошибка 500 очень часто вызвана синтаксической ошибкой в файле дополнительных конфигураций <code>.htaccess</code>. Например, неправильной записью правил перенаправления (RewriteRules).</p>
        <p><strong>Решение:</strong> Переименуйте файл <code>.htaccess</code> в <code>.htaccess_old</code> через менеджер файлов или FTP и попробуйте обновить страницу. Если сайт заработал — перегенерируйте правила с нуля (для WordPress достаточно зайти в Настройки -> Постоянные ссылки и просто нажать кнопку "Сохранить").</p>

        <h2>3. Превышение лимита оперативной памяти PHP (Memory Limit)</h2>
        <p>Если ваш веб-сайт использует сложные модули обработки изображений или делает крупные выборки из базы данных, скрипт может достичь максимального лимита памяти, выделенной для выполнения PHP процесса.</p>
        <p><strong>Решение:</strong> Увеличьте лимит оперативной памяти. Вы можете сделать это, добавив следующую строку в файл <code>.htaccess</code>:</p>
        
```apache
php_value memory_limit 512M
```

        <p>или непосредственно в конфигурационном файле <code>php.ini</code>:</p>
        
```ini
memory_limit = 512M
```


        <h2>4. Неправильные разрешения доступа к файлам и папкам</h2>
        <p>Слишком высокие права доступа (например, 777 на файлы) могут блокироваться системами безопасности сервера (suPHP, mod_security) для предотвращения несанкционированной записи данных.</p>
        <p><strong>Стандарт безопасности:</strong> Убедитесь, что все папки имеют права <strong>755</strong>, а все файлы — <strong>644</strong>. Вы можете быстро исправить разрешения через терминал с помощью следующих команд:</p>
        
```bash
find . -type d -exec chmod 755 {} \;
find . -type f -exec chmod 644 {} \;
```


        <h2>Заключение</h2>
        <p>Ошибка 500 Internal Server Error почти всегда кроется в мелочах: ошибка синтаксиса в файле конфигурации или нехватка системных ресурсов. Используя последовательную диагностику через чтение логов ошибок, вы сможете вернуть ваш сайт в строй за считанные минуты.</p>
